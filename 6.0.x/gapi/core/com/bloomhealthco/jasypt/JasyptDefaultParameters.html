[Groovy] Class JasyptDefaultParameters

    • com.bloomhealthco.jasypt.JasyptDefaultParameters 
    • @groovy.transform.CompileStatic
class JasyptDefaultParameters
extends java.lang.Object

      Resolves the default parameters passed to the encrypted GORM user types. Shared by the Hibernate 5 and Hibernate 7 flavours of the plugin, so both are configured the same way.

        • static java.util.Map<java.lang.String, java.lang.Object> getJasyptConfig()

          You can create a jasypt stanza in your grails-app/conf/application.yml (or application.groovy). This stanza can either override the default encryptor name and set a new encryptorRegisteredName that you define in your Spring resources.groovy file, ex: jasypt: encryptorRegisteredName: fooBar otherwise, you can actually configure the encryptor right there using the other properties available in org.jasypt.hibernate5.type.ParameterNaming, ex with triple-DES: jasypt: algorithm: PBEWithMD5AndTripleDES password: s3kr1t keyObtentionIterations: 1000 or Bouncy Castle AES: jasypt: algorithm: PBEWITHSHA256AND128BITAES-CBC-BC providerName: BC password: s3kr1t keyObtentionIterations: 1000

          Returns:
          the jasypt config specified in the application configuration

        • static java.util.Properties mergeWithDefaults(java.util.Properties parameters)

          Merges the default parameters with the parameters given in the domain mapping. Parameters from the mapping take precedence. Values are stored as is. As java.util.Properties#getProperty(java.lang.String) only returns String values, non-String config values (e.g. a numeric keyObtentionIterations from YAML) are ignored by the user types. This has always been the behaviour of the plugin, and changing it would change the encryptor settings and break decryption of existing data.

          Parameters:
          parameters - the parameters given to the user type, may be null
          Returns:
          the merged parameters
